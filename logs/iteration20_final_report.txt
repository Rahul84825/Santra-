3. UI LAG ELIMINATION & RENDERING PERFORMANCE
--------------------------------------------------------------------------------
Root Causes of Lag Identified:
1. paintEvent in MainWindow ran an uncached 60 FPS QTimer loop drawing 250+ vector scanlines 
   and radial gradients across 1240x820 pixels on the main Qt GUI thread.
2. Conversation view previously executed _rebuild_log_view(), tearing down and rebuilding 
   all 50 QWidget trees on every single message turn or streaming chunk.
3. Telemetry queries ran without caching or window-state awareness.

Remediations Applied:
1. Removed scanline loops and full-window vector gradients from MainWindow.paintEvent(). 
   Surfaces are styled via Qt hardware-accelerated stylesheets.
2. Implemented incremental message addition: _append_turn_widget() creates and appends only 
   the newly arrived card (O(1) operation). A max-bound of 60 cards is maintained by pruning 
   the oldest widget from the top.
3. Throttled background telemetry to a 1.5s interval.
4. Added changeEvent, hideEvent, and showEvent handlers: When SANTRA is minimized or hidden 
   to the system tray, all telemetry and HUD timers immediately stop, dropping idle CPU/GPU 
   utilization to ~0.0%.

5. FORENSIC AUDIT OF WINDOWS PROCESS EXIT 3221226505 (0xC0000409)
--------------------------------------------------------------------------------
Exit code 3221226505 corresponds to NTSTATUS 0xC0000409:
    STATUS_STACK_BUFFER_OVERRUN (Fast Fail / __fastfail)
Occurs in Qt6Core.dll when an invariant check fails or cross-thread violation occurs.

Root Causes Identified & Fixed:
1. Cross-Thread QTimer Manipulation in ui/panels/spotify_panel.py:
   A raw background Python thread (threading.Thread(target=self._run_poll)) was invoking 
   QTimer.singleShot(0, self._apply_poll_data) directly. In Qt6 on Windows, calling QTimer 
   from a thread lacking a QEventLoop triggers an unrecoverable qFatal abort (0xC0000409).
   Fix: Replaced with a thread-safe Qt Signal:
       sig_poll_data_ready = pyqtSignal(object, list)
   emitted from the worker thread and queued to the main GUI thread slot.
2. Destructive setWindowFlags in ui/panel_controller.py:
   Calling setWindowFlags() on active top-level windows destroys and recreates the Win32 HWND. 
   If modal dialogs or sub-panels were in flight, the Windows message pump dereferenced stale 
   HWND pointers.
   Fix: Replaced destructive flag cycling with non-destructive raise_() and activateWindow().
